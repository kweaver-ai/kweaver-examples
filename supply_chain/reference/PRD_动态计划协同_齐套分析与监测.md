## 1. 业务背景与场景

### 1.1 核心业务问题

制造企业在生产前必须回答三个问题：

1. **能否按期开工？** — 按 BOM 展开，所有物料最晚什么时候必须到位？
2. **哪些物料有风险？** — 当前供应链执行进度，哪些物料可能延误？
3. **产品最早何时能交付？** — 如果有延误，延迟多少天？瓶颈在哪？

这三个问题分别对应：**齐套倒排**、**供应状态判定**、**交期分析**。

### 1.2 两种监测任务

|      | 单产品监测任务                 | 多产品监测任务（大预测单）            |
| ---- | ----------------------- | ------------------------ |
| 监测范围 | 一个产品                    | 一张预测单下所有产品               |
| 创建方式 | 三步引导（选产品 → 选预测单 → 确认参数） | 输入预测单号直接创建               |
| 甘特图  | 单产品 BOM 倒排              | 多产品 BOM 倒排（各产品独立分组，同一视图） |
| 物料清单 | 单产品物料                   | 合并物料清单，区分独占物料和共用物料       |
| 核心差异 | 关注单个产品的齐套状态             | 关注跨产品共用物料的需求汇总与库存分配      |

两者是**并列的监测任务类型**，不是包含关系。多产品监测任务直接承载监测能力，不依赖也不生成单产品监测任务。

### 1.3 客户痛点

| 痛点                  | 影响                             |
| ------------------- | ------------------------------ |
| 大预测单包含多产品，只能逐个建任务   | PMC 在多个任务间切换，无法感知跨产品物料冲突       |
| 多产品共用同一物料时各自独立计算需求  | 采购决策失准，可能重复采购或漏采               |
| 多级 BOM 下共用物料总需求量不透明 | PMC 无法快速核算某物料应备多少货             |
| 共用物料对应多个交期时无明确倒排基准  | 物料催办节奏混乱，存在因共用物料延误导致某产品无法开工的风险 |

## 2. 业务对象（基于供应链知识网络）

### 2.1 对象类型

以下业务对象均存储在 KWeaver 知识网络中，通过 Ontology API 查询。

| 业务对象            | 知识网络对象类型                       | 业务含义                                  |
| --------------- | ------------------------------ | ------------------------------------- |
| **产品**          | `supplychain_hd0202_product`   | 可销售/可生产的成品或半成品，是 BOM 的根节点             |
| **需求预测**        | `supplychain_hd0202_forecast`  | 客户需求预测单，包含产品编码、预测数量、交货截止日。大预测单包含多个产品行 |
| **BOM（物料清单）**   | `supplychain_hd0202_bom`       | 产品的多层物料结构，定义"产品由哪些子件组成、每个子件用多少"       |
| **物料**          | `supplychain_hd0202_material`  | 原材料、零部件、半成品的主数据，包含标准交期（采购/生产提前期）      |
| **MRP（物料需求计划）** | `supplychain_hd0202_mrp`       | ERP 的 MRP 运算结果，标识物料是否有净需求缺口           |
| **PR（采购申请）**    | `supplychain_hd0202_pr`        | 采购申请单，由 MRP 触发，审批后转为采购订单              |
| **PO（采购订单）**    | `supplychain_hd0202_po`        | 采购订单，包含供应商承诺交货日和实际收货量                 |
| **库存**          | `supplychain_hd0202_inventory` | 物料的仓库库存，区分账面库存、可用库存、已预留库存             |
| **MPS（生产工单）**   | `supplychain_hd0202_mps`       | 工厂生产计划/工单，包含生产数量和排产时间                 |

### 2.3 数据关联链

系统中存在**两条平行的精确关联链**，分别用于外购件和自制件：

**采购链（外购/委外件）：**

```
预测单（Forecast.billno）
  → MRP（rootdemandbillno = Forecast.billno）
    → PR（srcbillnumber = MRP.billno）
      → PO（srcbillnumber = PR.billno）
```

**生产链（自制件）：**

```
预测单（Forecast.billno）
  → MRP（rootdemandbillno = Forecast.billno，materialattr_title = 自制）
    → MPS 生产工单（sourcebillnumber = MRP.billno）
```

两条链的起点都是**预测单 → MRP**，在 MRP 层按物料类型分叉：

- 外购/委外件 → PR → PO（采购执行）
- 自制件 → MPS（生产执行）

每一层通过上一层的单号精确关联，确保数据溯源准确。

### 2.4 关键业务约束

| 约束         | 规则                                                         |
| ---------- | ---------------------------------------------------------- |
| **主料口径**   | 所有 BOM 分析仅使用主料（`alt_priority == 0`），替代料不参与                 |
| **BOM 版本** | 同一产品可能有多个 BOM 版本，取任意版本即可（业务约定：各版本物料完全一致）                   |
| **可达性**    | BOM 记录必须从产品根节点 BFS 可达，游离节点不参与分析                            |
| **库存口径**   | 使用 `available_inventory_qty`（可用库存），非 `inventory_qty`（账面库存） |
| **在途量**    | PO 在途量 = `qty - actqty`（订单量 - 已收货量），仅取正数部分                 |

## 3. 核心业务逻辑

### 3.1 齐套倒排（计划视角）

#### 业务目标

> 要在计划日期完成生产交付，每个物料最晚什么时候必须到位？

#### 倒排规则

从交货截止日往前推算，逐层确定每个物料的时间窗口：

```
L0 产品:      |====生产周期====|交货截止日|
L1 子件A:   |==采购周期==|到位|
L1 子件B:   |===生产周期===|到位|
L2 原材料C: |=采购=|到位|
                           ↑ 每层的"到位日" = 上一层的"开工日 - 1天"
```

**具体计算：**

| 层级    | 结束日（endDate）     | 开始日（startDate）   |
| ----- | ---------------- | ---------------- |
| L0 产品 | 交货截止日（demandEnd） | endDate - 生产标准交期 |
| 子件    | 父级开工日 - 1天       | endDate - 甘特条长度  |

#### 标准交期（standardLeadtime）

物料从下单到收货的固有周期，是物料的**固有属性**，不因库存/MRP/PO 状态而改变：

| 物料类型 | 标准交期来源                            |
| ---- | --------------------------------- |
| 外购件  | `purchase_fixedleadtime`（采购固定提前期） |
| 委外件  | `purchase_fixedleadtime`（采购固定提前期） |
| 自制件  | `product_fixedleadtime`（生产固定提前期）  |

#### 甘特条长度（leadtime）

甘特图上物料条的长度代表"这个物料需要占用的时间"：

| 物料供需状态  | 甘特条长度      | 业务含义               |
| ------- | ---------- | ------------------ |
| 库存满足需求  | 1 天        | 物料已就绪，用窄条标记"已到位"   |
| 库存不满足需求 | 标准交期（最小1天） | 需要采购或生产，按标准周期排出时间段 |

#### 库存满足判断（两阶段）

**第一阶段（倒排时，简化判断）：**

倒排阶段尚未计算精确需求量，用以下简化规则初步判断：

- **有 MRP 缺口记录** → 不满足（ERP 的 MRP 运算已判定有净需求）
- **无 MRP 记录 且 可用库存+在途 > 0** → 暂定满足（甘特条=1天）
- **无 MRP 记录 且 无库存** → 不满足

> 注意：第一阶段只看库存/在途的"存在性"，不知道是否"够量"。

**第二阶段（BOM 展开后，精确修正）：**

BOM 展开计算出每个物料的精确净需求（`netRequirement = 需求量 - 可用库存 - 在途`）后：

- `canFulfillByInventory = netRequirement === 0` — 精确的数量感知判断
- 若 `canFulfillByInventory = false`（库存实际不足）但第一阶段误判为满足（甘特条=1天），则**修正**：甘特条恢复为标准交期，开始日重算

**典型案例：**

```
物料 102-000140：标准交期 126 天，在途 200 件，需求 12,000 件
第一阶段：在途 200 > 0 → 暂定满足 → 甘特条 = 1 天（错误）
第二阶段：净需求 = 12,000 - 0 - 200 = 11,800 > 0 → 不满足
修正后：甘特条 = 126 天，开始日前移 125 天（正确）
```

#### PO 到货不影响倒排

甘特图倒排是**计划视角**（理想情况），PO 到货是**现状视角**（实际执行）。两者不混淆：

- 甘特图只用标准交期倒排，展示计划时间轴
- PO 执行情况通过"交期分析"和"供应状态判定"独立反映

### 3.2 BOM 展开与净需求计算

#### 展开需求量

从产品计划数量出发，沿 BOM 路径逐层展开：

```
物料M对产品P的展开需求量 = 产品预测数量 × BOM路径各层 standard_usage 连乘积

示例（三层BOM）：
  产品P（预测100件）
    └─ 半成品A（用量 2）
          └─ 物料M（用量 3）
  → 物料M的展开需求量 = 100 × 2 × 3 = 600 个
```

若物料在 BOM 中存在多条可达路径，各路径用量**相加**。

#### 净需求计算

```
净需求（netRequirement） = 展开需求量 - 可用库存 - 在途数量
canFulfillByInventory = 净需求 === 0
```

- `canFulfillByInventory = true`：库存+在途能覆盖全部需求
- `canFulfillByInventory = false`：存在缺口，`bomShortageQty = 净需求`

### 3.3 物料供应状态判定（10 档体系）

每个物料根据以下规则**顺序判定**，命中即返回。

#### 输入

```
供给量 = 可用库存 + 在途数量
```

#### 判定流程

```
第一步：库存满足
  供给量 ≥ 展开需求量 → ⑩ sufficient（库存满足）

第二步：库存不足，按物料类型分支
  ┌─ 外购/委外
  │   ├─ 无 MRP → ① anomaly（数据异常，需 ERP 核查）
  │   ├─ 有 PO 且 PO 交期 ≤ 今天 → ⑤ po_overdue（PO 已逾期）
  │   ├─ 有 PO 且 PO 交期 > 需求截止日 → ② deadline_risk（交期风险）
  │   ├─ 无 PO 且 今天+标准交期 > 需求截止日 → ② deadline_risk（交期风险）
  │   ├─ 无 PR → ③ no_pr（未下 PR）
  │   ├─ 有 PR 且无 PO → ④ no_po（未下 PO）
  │   └─ 有 PO，未命中以上 → po_in_transit（PO 在途）
  │
  └─ 自制件
      ├─ 子件有缺口 → ⑥ child_short（子件有缺口，等待齐套）
      ├─ 子件无缺口 且无 MRP → ⑧ unscheduled（齐套未排产）
      └─ 子件无缺口 且有 MRP → ⑨ plan_gap（有计划但有缺口）
```

#### 风险等级与行动映射

| 风险等级            | 状态码                                  | 行动要求 |
| --------------- | ------------------------------------ | ---- |
| **danger（紧急）**  | anomaly, deadline_risk, po_overdue   | 立即处理 |
| **warning（警告）** | no_pr, no_po, child_short            | 限期跟进 |
| **info（信息）**    | unscheduled, plan_gap, po_in_transit | 关注即可 |
| **normal（正常）**  | sufficient                           | 无需处理 |

#### 状态文案

| 状态码                | 文案                                                            |
| ------------------ | ------------------------------------------------------------- |
| sufficient         | 外购/委外有MRP: "库存满足，注意MRP有记录"；无MRP: "库存满足，无需采购"；自制: "库存满足，暂无需生产" |
| anomaly            | "无MRP且库存不足，需ERP核查"                                            |
| deadline_risk（有PO） | "PO交期 {date} 超过需求截止日 {endDate}"                               |
| deadline_risk（无PO） | "标准交期 {standardLeadtime} 天已超截止日 {endDate}，现在下单也来不及"           |
| no_pr              | "有MRP缺口，尚未生成PR"                                               |
| no_po              | "PR已生成，尚未下达PO"                                                |
| po_overdue         | "PO交期已过 {days} 天，物料未到"                                        |
| po_in_transit      | "有MRP缺口，PO在途"                                                 |
| child_short        | "子件有缺口，等待齐套"                                                  |
| unscheduled        | "子料已齐套，未下达生产计划"                                               |
| plan_gap           | "库存缺口 {gap} 件，子料已齐套"                                          |

### 3.4 产品交期分析

#### 业务目标

> 按当前现状，产品能否按计划交付？如果不能，延迟多少天？哪些物料是瓶颈？

#### A 类延迟：排不下的物料

```
含义：按倒排计划，这个物料应该在某个过去的日期就开始采购，但到今天仍未下 PO。
      如果今天立刻下单，按标准交期算，最早到货日仍晚于计划到位日。

条件：倒排开始日 < 今天 且 无PO 且 库存不满足（canFulfillByInventory = false）
延迟天数 = (今天 + 标准交期) - 倒排结束日
预计到货日 = 今天 + 标准交期
```

#### B 类延迟：PO 超期的物料

```
含义：已经下了采购订单，但供应商承诺的到货日期晚于倒排计划要求的到位日期。

条件：有PO 且 PO到货日 > 倒排结束日 且 库存不满足（canFulfillByInventory = false）
延迟天数 = PO到货日 - 倒排结束日
预计到货日 = PO到货日
```

#### 延迟传导规则

- 一个底层物料延迟 N 天 → 其所有上层物料开工延迟 N 天 → 产品交付延迟 N 天
- 同层多个物料延迟时，取最大值（瓶颈决定）
- **产品预计延迟 = BOM 树中所有延迟物料的最大延迟天数**
- **产品预计交付日 = 计划交付日 + 产品预计延迟**

### 3.5 共用物料分析（多产品监测专用）

#### 识别规则

- **范围**：仅在同一预测单内，不跨预测单
- **口径**：主料（`alt_priority == 0`）
- **粒度**：物料编码，出现在 2 个及以上产品 BOM 中即为共用物料

#### 折算需求量

```
物料M对产品P的折算需求量 = 预测数量 × BOM路径各层用量连乘积
物料M的需求总量 = 所有关联产品的折算需求量之和
```

#### 倒排基准产品

共用物料的最晚到货时间，取关联产品中**交货截止日最早**的那个产品作为基准。

#### 库存分配建议

当共用物料库存不足以满足所有产品的需求时：

```
按交货截止日升序排列关联产品（最早交期优先）
remaining = 可用库存 + 在途数量
for each 产品（按交期优先）:
  建议分配量 = min(remaining, 该产品折算需求量)
  remaining -= 建议分配量
```

## 4. 业务场景

### 4.1 单产品监测

**触发条件**：用户选择一个产品，指定预测单号和交货截止日，创建单产品监测任务。

**场景流程：**

```
Step 1：查询产品的 BOM（仅主料），BFS 展开并过滤不可达节点
Step 2：查询所有涉及物料的主数据（获取标准交期）
Step 3：查询库存和在途 PO（获取供给量）
Step 4：查询 MRP → PR → PO 精确关联链（获取外购件采购执行状态）
Step 5：从 MRP 中筛选自制件单号（materialattr_title=自制），用于关联生产工单
Step 6：执行齐套倒排（计算每个物料的时间窗口）
Step 7：执行 BOM 展开净需求计算 + 甘特条修正
Step 8：对每个物料执行供应状态判定（10 档）
Step 9：执行产品交期分析（A/B 类延迟）
Step 10：查询关联生产工单（MPS.sourcebillnumber in [自制件MRP单号]），展示工单执行状态
```

**输出：**

- 甘特图：BOM 层级倒排时间线，每个物料显示状态色
- 物料卡片：标准交期、倒排时间范围、BOM 展开评估、供应状态
- 计划进度总结：A 类/B 类延迟物料清单，产品预计交付日
- 关键物料监测清单：全量物料 + 供应状态提示 + 风险着色
- 关联生产工单：自制件的工单状态（未开工/开工/完工）、计划与实际时间、合格入库数
- 每日监测报告：紧急行动项 + 跟进行动项

### 4.2 多产品监测（大预测单）

**触发条件**：用户输入预测单号，创建多产品监测任务。

**场景流程：**

```
Step 1：查询预测单下所有产品行及基本信息
Step 2：预热所有产品的公共数据（BOM、物料、库存、MRP、PR、PO）
Step 3：并行构建每个产品的甘特图（复用单产品倒排逻辑，含自制件MRP筛选）
Step 4：共用物料分析（识别共用物料、计算折算需求、生成分配建议）
Step 5：对全量物料执行供应状态判定
Step 6：查询关联生产工单（MPS.sourcebillnumber in [自制件MRP单号]）
```

**输出：**

- 多产品甘特图：每个产品独立分组（可折叠），共用物料标注"共用"标识
- 物料监测清单：合并视图，区分独占/共用，共用物料展示需求总量和分配建议
- 关联生产工单：跨产品的自制件工单汇总，按产品分组展示
- 汇总卡片：总产品数、已齐套/缺料产品数
- 每日监测报告：跨产品的紧急行动项

### 4.3 每日监测报告

**触发条件**：用户在任务详情页点击"生成监测报告"。

**行动项生成规则：**

| 供应状态          | 行动类型 | 行动描述                       |
| ------------- | ---- | -------------------------- |
| anomaly       | 紧急   | "无MRP且库存不足，需ERP核查"         |
| deadline_risk | 紧急   | "标准交期 {N} 天已超截止日，现在下单也来不及" |
| po_overdue    | 紧急   | "PO交期已过 {N} 天，物料未到"        |
| no_pr         | 跟进   | "有MRP缺口，需立即生成PR"           |
| no_po         | 跟进   | "PR已生成，需推进下达PO"            |
| child_short   | 跟进   | "子件有缺口，需优先解决子件缺料"          |

### 4.4 预警横幅

**触发条件**：任务详情页加载时自动展示，基于当前甘特图数据实时计算。

**预警维度（4 类）：**

| 预警类型     | 级别                                     | 触发条件                                                                   | 与供应状态关系                  |
| -------- | -------------------------------------- | ---------------------------------------------------------------------- | ------------------------ |
| 齐套倒计时    | 距 demandEnd ≤ 7 天→紧急；≤ 15 天→高；≤ 30 天→中 | 存在 `supplyStatus = shortage / anomaly` 的物料 **且** 距需求截止日 ≤ 30 天         | 任务级别预警，非物料级别（唯一不与供应状态重叠） |
| 缺口未下 PO  | 高                                      | `supplyStatus = shortage` 且 `poStatus ≠ has_po`                        | ≈ no_pr + no_po 的合集      |
| PO 超期未到料 | 高                                      | `poStatus = has_po` 且 `poDeliverDate < 今天` 且 `supplyStatus = shortage` | ≈ po_overdue             |
| 异常物料     | 中                                      | `supplyStatus = anomaly`                                               | = anomaly                |

> **设计说明**：后三类预警本质是物料供应状态判定（§3.3）的子集，以横幅形式聚合展示，帮助 PMC 快速识别当前最严重的问题。齐套倒计时是唯一的**任务级**预警，关注整体进度而非单个物料。

**展示形式**：

- 横幅显示 紧急 / 高 / 中 各多少项
- 可展开查看明细表（级别、类型、物料编码、物料名称、异常原因、截止时间）
- 无预警时显示绿色"当前无异常预警"

### 4.5 任务结束

**触发条件**：用户在任务详情页点击"结束任务"。仅 `status = active` 的任务可结束。

**结束流程：**

```
Step 1：入库检查（checkProductInbound）
  查询产品编码对应的库存记录（supplychain_hd0202_inventory）
  ├─ 无记录 → status = incomplete，提示"未发现产品入库记录"
  └─ 有记录 → status = completed
       取最新 inbound_date，inventory_qty 求和
       计算与 demandEnd 的差异天数
       ├─ 差异 ≤ 0 → "产品已按计划入库"
       ├─ 差异 1~30 天 → "比计划延迟 N 天"
       └─ 差异 > 30 天 → "差异超过1个月，请关注"

Step 2：生成总结报告（TaskSummaryReport）
  ├─ planVsActual：需求周期 vs 实际入库时间/数量
  ├─ productCompletion：需求数量、入库数量、完成率
  ├─ materialCompletion：物料总数、已下PO、未下PO、有缺口数
  └─ keyMaterialsSnapshot：关键物料快照（结束时刻状态）

Step 3：持久化
  写入 task.status / task.endedAt / task.summaryReport → localStorage
```

**结束状态：**

| 状态           | 含义  | 条件      |
| ------------ | --- | ------- |
| `completed`  | 已完成 | 产品有入库记录 |
| `incomplete` | 未完成 | 产品无入库记录 |

**总结报告展示**：已结束任务的详情页自动展示总结报告卡片（产品完成情况 + 物料完成统计）。

> **当前限制**：大预测单（`taskType = 'large-forecast'`）不支持结束流程，`endTaskWithReport` 直接返回 null。

### 4.6 任务导入导出

**业务目标**：支持任务数据的备份、迁移和共享。

**导出**：

- 入口：任务详情页"导出"按钮
- 格式：`.scb.json`（SupplyChainBrain 专用格式）
- 包含内容：任务配置 + 甘特图快照 + 关键物料清单
- 文件命名：`{任务名称}.scb.json`

**导入**：

- 入口：任务列表页"导入"按钮
- 接受 `.scb.json` 文件
- 导入后创建新任务（生成新 ID，状态重置为 active）

## 5. 业务行动

### 5.1 紧急行动（danger 级别 → 立即处理）

| 状态                 | 建议行动                         | 风险等级           |
| ------------------ | ---------------------------- | -------------- |
| anomaly            | ERP 中核查该物料的 MRP 运算状态，确认是否漏计划 | 信息核查           |
| deadline_risk（无PO） | 立即发起 PR 并推进 PO，联系供应商确认是否可加急  | high（发起PO不可撤销） |
| deadline_risk（有PO） | 联系供应商确认能否提前交货，评估替代料方案        | medium         |
| po_overdue         | 联系供应商跟踪物流，确认到货时间，必要时启动备选供应商  | high           |

### 5.2 跟进行动（warning 级别 → 限期跟进）

| 状态          | 建议行动                        |
| ----------- | --------------------------- |
| no_pr       | 在 ERP 中生成 PR 或确认 MRP 建议是否执行 |
| no_po       | 推进 PR 审批和 PO 下达             |
| child_short | 优先解决子件的缺料问题（递归诊断子件状态）       |

### 5.3 生产推送行动（自制件齐套时）

**触发条件**：自制件 + 距倒排开工日 ≤ 2天 + 子件无缺口（hasShortage = false）

**行动**：推送该物料到生产排产系统。

### 5.4 生产工单追踪（自制件关联 MPS）

**关联方式**：

```
Step 1：从 MRP 记录中筛选 materialattr_title = 自制 的条目，收集 selfMadeMrpBillnos
Step 2：查询 MPS（sourcebillnumber in [selfMadeMrpBillnos]），获取关联生产工单
Step 3：展示工单执行状态（未开工 / 开工 / 完工），匹配 MRP 投放时间
```

**展示内容**：

| 字段                                          | 含义                           |
| ------------------------------------------- | ---------------------------- |
| 工单号（billno）                                 | 生产工单编号                       |
| MRP需求号（sourcebillnumber）                    | 关联的 MRP 计划订单号                |
| 物料编码（material_number）                       | 工单生产的物料                      |
| MRP投放时间（droptime）                           | MRP 计划投放时间，来自 mrpDroptimeMap |
| 计划开工/完工（planstartdate / planfinishdate）     | 工厂排产时间                       |
| 实际开工/完工（actualstartdate / actualfinishdate） | 实际执行时间                       |
| 任务状态（taskstatus_title）                      | 未开工 / 开工 / 完工                |
| 合格入库数（stockinqty）                           | 已入库的合格品数量                    |

**工单完成判定**：`taskstatus_title === '完工'`

### 5.5 共用物料分配行动（多产品场景）

**触发条件**：共用物料库存不足以满足所有关联产品需求

**行动**：按交期优先级分配库存，展示分配建议供 PMC 决策。

## 6. 关联能力：需求承接分析

与本 PRD 描述的**齐套监测**并列、同属「动态计划协同」板块的能力：

| 文档                          | 说明                                                                                                                                           |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `docs/PRD_需求承接分析.md`（V2.0）  | **需求承接分析**：基于 KN 对象建模的结构化业务规则（Rule 1-7）；可售能力看板（BOM 瓶颈反推）+ 新需求分层供给匹配（pegging）；缺口跳转本模块                                                         |
| `docs/技术设计_需求承接分析.md`（v1.0） | 数据层复用 `planningV2DataService`（BOM/库存/PO）+ 有效仓库过滤；算法层复用 `productInventoryCalculator` + `bomExpander`；新建 `demandFulfillmentService` 实现 pegging |

**差异一句话**：齐套监测以**预测单与持续监测**为主；需求承接以**可售能力核算与点状/批量新需求**为主，二者互补。

**共享数据层**：BOM（`loadBOMByProduct`）、库存（`loadInventoryByMaterials` + `getValidWarehouses()`）、PO（`loadPOByMaterials`）的 Ontology 查询和有效仓库过滤完全复用。

## 7. 字段语义对照表

| 字段                       | 业务含义           | 取值规则                                                            |
| ------------------------ | -------------- | --------------------------------------------------------------- |
| `standardLeadtime`       | 标准交期时长（天）      | 外购/委外 → `purchase_fixedleadtime`；自制 → `product_fixedleadtime`   |
| `leadtime`               | 甘特条长度（天）       | 库存满足 → 1天；库存不足 → max(standardLeadtime, 1)；BOM 展开后精确修正           |
| `canFulfillByInventory`  | 精确满足判断         | BOM 展开净需求后 `netRequirement === 0`                               |
| `grossRequirement`       | BOM 展开需求量      | 预测数量 × BOM 路径各层用量连乘积                                            |
| `netRequirement`         | 净需求（缺口量）       | 展开需求量 - 可用库存 - 在途                                               |
| `startDate`              | 倒排开始日          | endDate - leadtime；BOM 展开修正后可能重算                                |
| `endDate`                | 倒排结束日（到位日）     | 父级开工日 - 1天                                                      |
| `hasMRP`                 | 是否有 MRP 记录     | ERP MRP 运算是否对该物料产生了计划订单                                         |
| `prStatus`               | PR 状态          | has_pr / no_pr / not_applicable                                 |
| `poStatus`               | PO 状态          | has_po / no_po / not_applicable                                 |
| `poDeliverDate`          | PO 最晚承诺交货日     | 所有关联 PO 中 deliverdate 的最晚日期                                     |
| `supplyStatus`           | 甘特条供应状态        | shortage / sufficient_no_mrp / anomaly / ready / ordered / risk |
| `hasShortage`            | 是否有缺口          | BOM 展开后 netRequirement > 0                                      |
| `selfMadeMrpBillnos`     | 自制件 MRP 单号列表   | MRP 中 materialattr_title = 自制 的 billno 集合，用于关联 MPS 工单           |
| `selfMadeMrpDroptimeMap` | 自制件 MRP 投放时间映射 | MRP.billno → MRP.droptime，供工单追踪展示                               |
